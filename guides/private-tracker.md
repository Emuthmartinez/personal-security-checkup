# A private progress note

Use only if the person wants a saved record. Agree where it lives, who can see it, and when to delete it. Choose a private note outside the repository and any public or shared folder. Do not create an account inventory by default. A generic resume sentence may be enough.

Never include credentials, recovery material, account identifiers, phone/email addresses, balances, identity documents, screenshots or raw evidence. “Recovery kit stored privately” is enough; do not record its contents or precise location. Keep private incident records with the user for official reporting, not in this tracker.

## Copyable template

The following is synthetic. Replace only with minimal non-sensitive descriptions in a private location.

| Item and scope | State | Basis and date | Owner / next action | Resume or review |
| --- | --- | --- | --- | --- |
| Main email recovery access | done | User confirmed they can use recovery method, 2026-10-24; agent did not inspect | User | Recheck after phone/recovery change |
| Main email two-step login | needs you | Recovery kit unavailable, 2026-10-24 | User: find kit privately; keep working session | Resume here next session |
| Bank A alerts | not checked | No review yet | User with agent instructions | Next short session |
| Work laptop settings | not applicable | Managed by employer | Employer support | Ask administrator if needed |

“Done” means that scoped action had evidence on that date. It does not mean all settings or future activity are safe. Specify whether the user reported completion or the agent observed a safe setting with authorization. Evidence can be a statement such as “settings shows two-step login on”; do not save a screenshot as proof.

Unknown access, unsupported features, an inaccessible source, stale evidence or a skipped test stay visible. A declined action is not done. Avoid a percentage or overall score. On return, ask what changed since the dated note; missing comparison information means “comparison unavailable.”

## Optional recurring setup record

Keep only consent date, approved scope, scheduler name, generic task ID, local time/timezone, next run, delivery channel, last successful test, last completed review, and how to pause/delete. An installed reminder and a completed review are separate states. Use “requested, readback pending” or “delivery unverified” when appropriate. Put no private account detail in reminder titles, notifications or calendar descriptions.
